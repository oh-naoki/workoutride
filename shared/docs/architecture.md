# WorkoutRide アーキテクチャ

このドキュメントでは、WorkoutRideアプリケーションの全体的なアーキテクチャについて説明します。

## システム概要

WorkoutRideは、サイクリングワークアウトを管理・追跡するためのアプリケーションです。システムは以下の主要コンポーネントで構成されています：

1. **モバイルアプリ（Flutter）** - ユーザーインターフェースとBLEデバイス接続
2. **バックエンドAPI（Rails）** - データ永続化とビジネスロジック
3. **データベース（PostgreSQL）** - ユーザーデータとワークアウト情報の保存

## フロントエンド（Flutter）

フロントエンドはFlutterで実装され、以下の主要機能を提供します：

- ユーザー認証
- BLEデバイス（パワーメーターなど）との接続
- リアルタイムのワークアウトデータ表示
- ワークアウト履歴の表示
- オフライン機能

### アーキテクチャパターン

フロントエンドはクリーンアーキテクチャに基づいて設計されています：

- **プレゼンテーション層** - UI（Widgets）とState Management
- **ドメイン層** - ビジネスロジックとユースケース
- **データ層** - リポジトリとデータソース（API、ローカルDB）

## バックエンド（Rails）

バックエンドはRuby on Railsで実装され、RESTful APIを提供します：

- ユーザー管理
- ワークアウトデータの永続化
- 分析と統計
- 同期機能
